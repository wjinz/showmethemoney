## 3. 배포 후 검증 시나리오 (Antigravity 담당)

push 완료 후 약 2~3분 뒤 production URL에서 다음 8건을 순서대로 확인합니다. 모든 항목은 plan v4 15장 검증 계획의 항목과 1:1 대응됩니다.

### 시나리오 A — 다이어리 탭 진입 + FAB 동작 (Issue 1)

1. 앱 첫 로드 시 다이어리 탭이 열려 있을 것 (App.jsx line 61 `useState("diary")`)
2. 하단 중앙 FAB(파란 원형 + 아이콘) 탭 → InputSheet가 슬라이드업 + 모드 탭 기본 "다이어리"
3. 모드 탭을 "지출 입력"으로 전환 → 항목 입력 UI 노출
4. 시트 외부 탭 또는 backdrop 클릭으로 닫힘

기대값: FAB이 QuickEntrySheet(지출 전용)이 아니라 InputSheet(다이어리 모드)를 연다.

### 시나리오 B — 항목별 카테고리/결제수단 (Issue 2)

1. FAB → "지출 입력" 모드
2. 첫 항목: 라벨 "점심", 금액 12000, 카테고리 식비, 결제 신용카드, 카드 선택
3. "항목 추가" 버튼 → 두 번째 항목: 직전 항목의 카테고리/결제수단/카드ID가 그대로 복사되어 있어야 함
4. 두 번째 항목 카테고리만 "교통"으로 변경, 결제 그대로
5. 저장 → 다이어리 카드에 두 항목이 각각 식비/교통으로 저장된 것 확인

기대값: 항목별 cat/payMethod/cardId가 독립적으로 저장되며, addItem 시 직전 값이 자동 시드된다.

### 시나리오 C — who 자동 적용 (Issue 3)

1. FAB → "지출 입력" 모드 진입
2. 화면에 husband/wife 선택 버튼이 보이지 않아야 함 (mode==='diary' 한정 렌더)
3. "다이어리" 탭으로 전환 → husband/wife 선택 버튼 노출
4. 저장 시 지출 모드는 자동으로 myRole(로그인한 본인)으로 저장됨

기대값: 지출 모드는 항상 myRole 자동 부여, 다이어리 모드만 who 선택 가능.

### 시나리오 D — 레이아웃 (Issue 4)

1. iOS Safari (노치/다이나믹 아일랜드) 기기에서 view-header 상단이 시스템 영역에 가리지 않음
2. 다이어리 카드 마지막 항목이 Nav + FAB에 가리지 않고 100px 여백으로 노출
3. month-banner가 좌우 16px 이상 안쪽으로 들어가지 않고 scroll-area padding(16px)에 깔끔히 정렬

기대값: safe-area-inset-top/bottom 정상 작동, scroll-area padding-bottom 100px 적용.

### 시나리오 E — 이름 편집 + 초기화 세분화 (Issue 5, 6)

1. 설정 → "기본 정보" 탭 → 인라인 편집 패널이 펼쳐지며 husband/wife 입력란 노출
2. 두 이름 변경 후 저장 → 다이어리 카드 헤더에 즉시 반영, Supabase 동기화
3. 설정 → "데이터 초기화" 탭 → 6개 옵션 패널: 지출 / 고정비·할부 / 예산 / 다이어리 / 사용자 설정 / 전체
4. "다이어리 초기화" 클릭 → confirm 팝업 → 다이어리 배열만 비워지고 tx 등은 그대로

기대값: alert 차단 없음, 6분류 모두 정상 동작.

### 시나리오 F — 예산 잔액 = tx 단일 합산 (Issue 7 + Antigravity-4)

1. 다이어리에서 지출 모드로 항목 2개(합 30,000원) 저장
2. 동일 월 EntryView 또는 QuickEntrySheet에서 일반 지출 1건(20,000원) 추가
3. 다이어리 탭 month-banner의 "이번 달 총 지출"이 50,000원 (30,000 + 20,000)으로 표시
4. 다이어리에서 저장한 지출은 tx 배열에도 자동 등록되어 있고 (`source_id` = diary.id), DashboardView 통계에 반영

기대값: 다이어리 합산 + tx 합산 이중 카운트 없음. tx만 합산해도 다이어리 입력분이 빠지지 않음.

### 시나리오 G — 이미지 압축 + 오프라인 IDB (Antigravity-1, 3)

1. 다이어리 모드에서 사진 첨부(원본 5MB JPEG 권장) → 자동 압축 (max 800px, WebP 0.82)
2. Supabase 저장 후 payload 사이즈 < 1MB 확인 (Network 탭)
3. 기기 오프라인 전환 → 사진 포함 다이어리 추가 저장 → IDB queue에 들어감
4. 온라인 복구 → 토스트 "오프라인 내역 N건 동기화 완료" + 파트너 기기에 즉시 반영

기대값: 5MB 이미지가 약 100~300KB로 압축, 오프라인 큐 flush 시 다이어리 항목 누락 없음.

### 시나리오 H — mask_details + 오늘의 질문 (Antigravity-2, 5, 6)

1. husband 기기: 지출 모드 → "세부 내역 숨기기" 토글 ON, "파트너와 총액 공유" 토글 ON
2. wife 기기: 해당 다이어리 카드는 본문/expenseItems 비공개 + "남편님이 38,979원 지출했습니다" 메시지만 노출, 카드 푸터 태그는 "총액만 공유"
3. 다이어리 탭 헤더의 "오늘의 질문"이 매일 다른 문구 (32개 중 month*31+date % 32 인덱스)
4. 스크롤 시 일자별 day-label이 상단에 sticky하게 따라옴

기대값: shared(본문 공유)와 mask_details(세부 마스킹) 의미 분리 정상, 일자 변동 시 질문 자동 갱신, sticky 동작.

## 8. 미해결 의문점 (Antigravity가 결정 필요)

다음은 본 작업에서 결정 보류한 사항으로, 검증 단계에서 디자인/PM 판단 필요.

1. **다이어리 모드 who-selector 장기 제거 여부**
   plan v4 [Claude Issue 3 추가 개선]: "다이어리 모드의 who 선택도 장기적으로 제거 고려. 내 다이어리는 항상 myRole, 파트너 다이어리는 Realtime 수신 구조가 더 명확."
   → 검증 시 husband/wife 동시 입력 케이스가 있는지 확인하고 결정.

2. **mask_details 기본값**
   현재 false. 시나리오 H에서 사용자가 토글 On 빈도가 낮다면 default true로 전환 검토.

3. **다이어리 데이터의 BudgetView 노출 정책**
   현재 다이어리 expense는 tx에 자동 등록되어 BudgetView에서도 카운트됨. 다이어리 입력분만 별도 라벨로 강조할지 결정.

4. **개인 지출(`is_private`)과 다이어리의 관계**
   PrivateWalletView의 is_private tx도 합산되는지, 아니면 다이어리는 공동 가계만 다루는지 정책 확정 필요.
