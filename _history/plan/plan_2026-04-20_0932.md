# [카드 정산하기 기능 구현 계획]

작성일시: 2026년 4월 20일 09:32

사용자가 이번 달 카드 결제일 이전에 미리 결제비를 계산하고, 총 현금 잔액과 고정비를 비교해 자산의 과부족분을 확인할 수 있는 '월별 카드 정산 계산기' 기능을 구축합니다.

---

## 🚀 1. 구현 목표 및 User Review 사항
**핵심 목표:** 
- 월별 카드 결제 대금과 보유 현금을 대조하는 직관적인 정산 계산기 컴포넌트 추가
- 과거 계산 내역(월 단위 기록) 조회 및 당월 결제 증감 추이 표출

**사용자 결정(합의) 완료 사항:**
> [!IMPORTANT]
> **데이터베이스 설계 원칙:** 기존의 오프라인 큐 및 동기화 무결성을 지키기 위해, `household_data` 테이블에 새로운 레코드를 생성하여 `settlements`라는 키에 월별 정산 배열 데이터를 동기화합니다. (승인됨)
> **디자인 접근 포인트:** 
> 1. 정산기능의 메인 진입점은 **"설정(SettingsView)"** 페이지 하위 메뉴 버튼으로 배치합니다.
> 2. 작성된 최근 정산의 요약 정보(현금 과부족분 등)를 **대시보드(DashboardView)** 상단 혹은 전용 요약 위젯 공간에 추가로 표시해 접근성과 인지성을 높입니다.

### [✅ 완료] Phase 2: 정산기 기본 프레임 및 계산 로직 (`src/views/SettlementView.jsx` 신설)
완전히 새롭고 독립된 뷰(모달 또는 하위 페이지 형식)를 만들어냅니다.
*   **히스토리 리스트 모드**: 
    - 이전 월의 배열 기록(예: `2026-03`)을 렌더링하고 총 사용액 및 부족금액 요약 카드를 보여줍니다.
    - 월별 한 건만 존재하도록 저장 시 같은 `date`를 upsert 방식으로 오버라이드.
*   **현재 정산 입력 모드**: 
    - `cards` 배열을 순회하여 사용자가 갖고 있는 모든 카드 항목별로 `expectedAmount(청구 예정금액)` 숫자 인풋을 제공합니다.
    - 입력란 주변에 `paymentDay(결제일)` 등 카드별 결제 주기 명세를 미니 텍스트로 보조 출력합니다.
    - 이전 달 배열(월단위 인덱스 산술 활용)을 찾아 현재 카드의 청구액과 비교(`당월 예정액 - 지난달 예상액 = 증감액`), 빨간색(+증가)과 파란색(-감소) 라벨을 카드 입력란 위에 부착시킵니다.
    - 총 보유현금과 현금 고정비 입력란 제공. (고정비의 경우 `fixed` 배열 데이터를 기반으로 `cardId`가 없는 총합을 Default Placeholder 값으로 자동 추산하여 제안).
    - **자동 연산 로직**: `Shortage(과부족액) = currentCash - fixedCash - sum(cardBills)` 시각화.

    > [!NOTE] **[Claude][✅ 반영완료] `fixedCash` 자동 제안 기능** — 앱에는 이미 `fixed` 배열(FixedItem[])이 있습니다. `cardId` 필드가 없는 항목이 현금 고정비입니다. 아래처럼 자동 계산된 값을 `fixedCash` 입력란의 기본값으로 제안하면 UX가 크게 개선됩니다:
    > ```javascript
    > const autoFixedCash = fixed
    >   .filter(f => !f.cardId)
    >   .reduce((sum, f) => sum + f.amount, 0);
    > ```
    > 이 값을 placeholder 또는 "자동 계산" 버튼으로 제공하고, 사용자가 수동으로 수정할 수 있게 하면 좋습니다.

    > [!NOTE] **[Claude][✅ 반영완료] 카드 결제 주기 정보 표시 제안** — `cards` 배열의 `CardItem` 타입에는 `paymentDay`, `billingStartDay`, `billingEndDay`, `billingEndNextMonth` 필드가 있습니다(constants/index.js:4). 각 카드 입력란 아래에 "청구 기간: 전월 15일 ~ 당월 14일 / 결제일: 매월 25일" 같은 정보를 작게 표시하면 사용자가 어떤 기간의 지출이 포함되는지 확인하는 데 도움이 됩니다.

    > [!NOTE] **[Claude][✅ 반영완료] 이전 달 조회 로직** — `date` 필드가 "YYYY-MM"이라면:
    > ```javascript
    > const [y, m] = currentDate.split('-').map(Number);
    > const prevDate = m === 1
    >   ? `${y - 1}-12`
    >   : `${y}-${String(m - 1).padStart(2, '0')}`;
    > const prevSettlement = settlements.find(s => s.date === prevDate);
    > ```

    > [!NOTE] **[Claude][✅ 반영완료] 월별 1건 유지 정책 결정 필요** — 같은 달에 정산을 여러 번 저장하면 히스토리에 중복이 생깁니다. 저장 시 같은 `date`("YYYY-MM")의 기존 항목을 덮어쓰는 upsert 방식을 권장합니다:
    > ```javascript
    > const newSettlements = settlements.filter(s => s.date !== item.date);
    > setSettlements([...newSettlements, item]);
    > ```
