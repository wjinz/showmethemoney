### P0-1. DashboardView 이중 지출 카운팅

**파일:** `src/views/DashboardView.jsx`

**원인:**  
`handleDiarySave` (App.jsx)는 diary type='expense' 저장 시 `addTxBatch`로 tx에도 동시 기록한다 (Antigravity-4).  
그런데 DashboardView는 `tx`를 diary 형태로 변환한 `txAsDiaries`와 `diaries` 배열을 그대로 합산한다.  
결과적으로 동일 지출이 diaries 배열과 tx 배열 양쪽에 존재하여 합산 금액이 2배가 된다.

**현재 코드 (오류):**
```js

  id: t.id,
  type: 'expense',
  // ...
}));
const mergedTx = [...diaries, ...txAsDiaries]; // diaries 중 type='expense'와 tx가 중복

const monthRecords = mergedTx.filter(d =>
  d.date.startsWith(currentMonth) && d.type === 'expense'
);
const hSpent = monthRecords
  .filter(d => d.who === 'husband')
  .reduce((s, d) => s + (d.totalSpent || 0), 0); // ← 이중 합산
```

**수정안:**  
DiaryView.jsx가 이미 올바른 방식을 사용한다 — `tx` 배열만으로 월 지출을 계산.  
DashboardView도 동일하게 `tx`를 단일 소스로 사용하고, diary는 감성/이모지 통계에만 활용한다.

```js
// DashboardView.jsx 수정

  tx.filter(t => typeof t.date === 'string' && t.date.startsWith(currentMonth)),
  [tx, currentMonth]

const hSpent = monthTx.filter(t => t.who === 'husband').reduce((s, t) => s + (t.amount || 0), 0);
const wSpent = monthTx.filter(t => t.who === 'wife').reduce((s, t) => s + (t.amount || 0), 0);
const totalSpent = hSpent + wSpent;

// catStats도 tx 기반으로 계산
const catStats = useMemo(() => monthTx.reduce((acc, t) => {
  if (!t.cat) return acc;
  acc[t.cat] = (acc[t.cat] || 0) + (t.amount || 0);
  return acc;
}, {}), [monthTx]);

// diaries는 이모지/감성 통계에만 사용 (type='diary'만 필터)
const monthDiaryOnly = diaries.filter(d =>
  d.date.startsWith(currentMonth) && d.type === 'diary'

```

> **[Antigravity]** DashboardView는 리렌더링이 잦은 위젯 구조이므로, 위 계산 로직은 반드시 `useMemo`를 사용하여 tx 배열이 바뀔 때만 실행되도록 보장해야 합니다. 또한, `ReportView.jsx` 등 다른 통계 뷰에서도 이와 유사한 이중 합산 로직이 있는지 전수 조사가 필요합니다.

### P0-2. SOS 채널 unsubscribe 누락 (메모리 누수)

**파일:** `src/App.jsx`, `src/utils/supabase.js`

**원인:**  
`db.subscribeSos`는 `sos:${hid}` 채널을 `_channels` 맵에 등록하지만,  
useEffect cleanup에서는 `db.unsubscribe(householdId)`만 호출한다.  
이 함수는 `realtime:household:${hid}` 채널만 제거하므로 SOS 채널이 계속 살아있다.  
컴포넌트가 마운트/언마운트를 반복하면 채널이 누적 등록된다.

**현재 코드 (오류):**
```js
// App.jsx — subscribeSos useEffect
useEffect(() => {
  if (!setupDone || !householdId) return;
  db.subscribeSos(householdId, (req) => { ... });
  // ❌ cleanup 없음 — SOS 채널 누수
}, [setupDone, householdId, myRole, addToast]);
```

**수정안:**
```js
// src/utils/supabase.js — db 객체에 추가
unsubscribeSos(hid) {
  const channelName = `sos:${hid}`;
  const ch = this._channels.get(channelName);
  if (ch) {
    supabase.removeChannel(ch);
    this._channels.delete(channelName);
  }
},

// App.jsx — SOS useEffect cleanup 추가
useEffect(() => {
  if (!setupDone || !householdId) return;
  db.subscribeSos(householdId, (req) => { ... });
  return () => { db.unsubscribeSos(householdId); }; // ✅ cleanup
}, [setupDone, householdId, myRole, addToast]);
```

> **[Antigravity]** 향후 구독 채널이 늘어날 경우를 대비해, db 객체 내에 모든 활성 채널을 한 번에 정리하는 `unsubscribeAll(hid)` 메서드 도입을 강력히 권장합니다.

```js
// HistoryView.jsx:11 — 오류 (빼면 UTC 방향으로 더 이동)

  selectedDate.getTime() - selectedDate.getTimezoneOffset() * 60000

// dailyExpenses 렌더링에서 반대 방향으로 다시 보정 → 이중 오류
```

```js
// HistoryView.jsx 수정 — 로컬 날짜 문자열 변환 헬퍼 사용
```

### P1-4. diaries JSONB blob 사진 용량 폭발 위험

**파일:** `src/components/InputSheet.jsx`

**원인:**  
다이어리 사진은 base64로 `photos[]`에 저장된다.  
`compressImage`가 800px / WebP 0.82로 압축해도 1장당 ~150-200KB, 3장이면 ~600KB.  
이 전체가 `household_data` key='diaries'에 하나의 JSONB 배열로 저장되며  
항목이 쌓일수록 매번 전체 배열을 덮어쓰는 비용과 Realtime 브로드캐스트 크기가 폭등한다.

**수정안 1단계 (즉시):**
```js
// src/components/InputSheet.jsx — handleFiles 함수
const dataUrl = await compressImage(file, {
  maxWidth: 600,          // 800 → 600
  quality: 0.65,          // 0.82 → 0.65
  format: 'image/webp',
});
setPhotos(p => [...p, dataUrl].slice(0, 2)); // 최대 3장 → 2장
```

**수정안 2단계 (중기 — Supabase Storage 분리):**
```js
// 사진을 Storage에 업로드하고 URL만 저장
async function uploadPhoto(file, householdId) {
  const compressed = await compressImage(file, { maxWidth: 600, quality: 0.65 });
  const blob = await fetch(compressed).then(r => r.blob());
  const path = `${householdId}/${Date.now()}.webp`;
  const { data, error } = await supabase.storage
    .from('diary-photos').upload(path, blob);
  if (error) throw error;
  return supabase.storage.from('diary-photos').getPublicUrl(data.path).data.publicUrl;
}
```

> **[Antigravity]** 2단계(Storage 분리) 전까지는 '설정' 메뉴에 '다이어리 캐시/사진 정리' 기능을 추가하여 6개월 이상 된 데이터의 사진 base64를 선택적으로 제거할 수 있는 유틸리티를 제공해야 합니다. 또한 Storage 도입 시, 기존의 Base64 데이터를 자동으로 Storage로 옮기고 URL로 치환해주는 '데이터 마이그레이션 스크립트' 설계가 선행되어야 데이터 폭증 문제를 근본적으로 해결할 수 있습니다.

### P7-1. 카드 이용기간 합산 로직 확인

**현재 상태:**  
`getBillingPeriod` (helpers.js)는 `cycleStart` ~ `cycleEnd`를 정확히 계산하고 있다.  
그러나 이 기간을 실제 tx 합산에 적용하는 뷰가 명확하지 않다.  
`SettlementView`는 카드별 청구액을 수기로 입력받으며, `getBillingPeriod`가 연동되어 있지 않다.

```js
// helpers.js getBillingPeriod — 로직 자체는 정상이므로 사용 위치 확인이 핵심
// CardView.jsx에서 preview 표시에만 사용 중 — 합산 연동 없음

// 권장: SettlementView에서 카드별 tx 합산 참고값 표시
function getCardBillingTotal(card, tx) {
  const { cycleStart, cycleEnd } = getBillingPeriod(card);
  return tx
    .filter(t => t.cardId === String(card.id))
    .filter(t => {
      const d = new Date(t.date + 'T00:00:00');
      return d >= cycleStart && d <= cycleEnd;
    })
    .reduce((s, t) => s + t.amount, 0);
}

// SettlementView의 각 카드 입력란 옆에 참고값 표시

</span>
```

### P7-2. AI 추천 예산 한도 초과 버그 — root cause 특정

**원인 (코드 분석으로 확인):**  
`BudgetTab`의 가용 예산 계산과 `runLocalAI`에 전달되는 파라미터가 다르다.

```js

  totalSalary - fixedTotal - installTotal - (salary.savingsTarget || 0) - allowanceTotal  // ← allowanceTotal 포함
);
const monthlyAvail = Math.round(monthlyAvailRaw * utilTarget / 100);

// runAI 호출 — allowanceTotal이 전달되지 않음
body: JSON.stringify({
  totalSalary, fixedTotal, installTotal,
  savingsTarget: salary.savingsTarget,
  catHistory, utilizationTarget: utilTarget
  // ❌ allowanceTotal 누락
})

// runLocalAI 내부 — allowanceTotal 없이 계산

// ← BudgetTab의 monthlyAvailRaw보다 allowanceTotal만큼 큼
// → AI 추천 합계 > BudgetTab.monthlyAvail → 한도 초과 표시
```

**수정안:**
```js

  setAiLoading(true);

const runLocalAI = (totalSalary, fixedTotal, installTotal, savingsTarget, catHistory, utilizationTarget = 100, allowanceTotal = 0) => {
  const rawAvail = Math.max(0, totalSalary - fixedTotal - installTotal - savingsTarget - allowanceTotal); // ✅ allowanceTotal 차감
  const monthlyAvail = Math.round(rawAvail * Math.min(Math.max(utilizationTarget, 50), 100) / 100);
  // ...
  // 추가: 1000원 절사 후 합계가 monthlyAvail을 초과하는 경우 보정
  const suggestedTotal = Object.values(suggested).reduce((s, v) => s + v, 0);
  if (suggestedTotal > monthlyAvail) {
    const scale = monthlyAvail / suggestedTotal;
    Object.keys(suggested).forEach(k => {
```
