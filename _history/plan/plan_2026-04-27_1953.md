## 🛠️ 최종 제안된 변경 사항 (피드백 반영)

### 1. 데이터 모델 확장 (Type-First)
`SettlementItem` 타입을 확장하여 부부 개별 현금 및 기타 비용 내역을 관리합니다.

```javascript
/** 
 * @typedef {{ label: string, amount: number }} ExtraExpense
 * @typedef {{ id: number, date: string, cardBills: CardBill[], fixedCash: number, husbandCash: number, wifeCash: number, extraExpenses: ExtraExpense[], expectedShortage: number, salary?: number }} SettlementItem 
 */
```

> [claude] 데이터 모델 보강 제안:
>
> 1. **`ExtraExpense`에 `id` 필수**: 동적 추가/삭제 시 React key 충돌과 부분 업데이트 안정성 확보.
>    ```javascript
>    /** @typedef {{ id: number, label: string, amount: number, cat?: string }} ExtraExpense */
>    ```
>    `cat?` 추가로 어느 카테고리 외 지출인지 추적 가능 → 추후 통계 가시화에 활용.
>
> 2. **`currentCash` 하위 호환 유지**: 현재 코드(SettlementView.jsx L54)에 `salary ?? currentCash ?? 0` fallback 존재. 새 스키마는 다음 마이그레이션 경로를 따르도록 명시.
>    ```javascript
>    // load 시점 자동 마이그레이션 (App.jsx loadShared 또는 SettlementView useEffect)
>    const husbandCash = existingData.husbandCash ?? Math.floor((existingData.currentCash ?? existingData.salary ?? 0) / 2);
>    const wifeCash    = existingData.wifeCash    ?? Math.ceil ((existingData.currentCash ?? existingData.salary ?? 0) / 2);
>    ```
>    구버전 데이터 무손실 보장. `currentCash`/`salary`는 deprecated 표시만 하고 즉시 제거하지 않음.
>
> 3. **`expectedShortage` 계산 공식 명문화** (typedef 옆 주석으로):
>    ```
>    expectedShortage = (husbandCash + wifeCash) − fixedCash − Σ(cardBills.expectedAmount) − Σ(extraExpenses.amount)
>    ```
>    음수 = 부족, 양수 = 흑자. SettlementView L105의 `calcShortage` 식을 그대로 확장.
>
> 4. **새 필드 모두 `optional`로 정의 권장**: `?` 없이 `husbandCash: number`로 두면 기존 settlements 배열에 대해 `validate.js`가 strict 모드에서 throw할 수 있음. App.jsx L520 `validate(key, newValue, { strict: key === 'cards' })`는 settlements는 strict가 아니지만, 안전을 위해 `husbandCash?: number, wifeCash?: number, extraExpenses?: ExtraExpense[]`로 시작 후 단계적으로 required 전환.

- **옵션 자동화**: '총액 공유' 및 '세부 내역 숨기기'를 기본값(`true`)으로 고정하고 UI에서 제거.

> [claude] InputSheet 보강 제안:
>
> 1. **메모 필드 제거 시 후속 영향**:

> 2. **Budget Insight 칩 — 정확한 계산 공식 명시 필요**:
>    ```javascript
>    // useBudget()에서 tx, budgets 가져와 useMemo
>    const currentMonth = today_str().slice(0,7);
>    const catSpent = useMemo(() => tx
>      .filter(t => t.date?.startsWith(currentMonth) && t.cat === it.cat)

>    - `0.2 ~ 0.5` → 노랑 (`var(--accent)`)
>    - `< 0.2` 또는 음수 → 빨강 (`var(--danger)`)

>    - 현재 코드에서 `expShared`(파트너에게 총액 공유)와 `maskDetails`(세부 내역 숨김)는 의미가 분리됨(Antigravity-2, PROJECT_HISTORY 16단계). 둘 다 true 고정은 "총액 공유 + 세부 마스킹"으로 사실상 부부 모두에게 합계만 보이게 됨 → 다이어리 중심 앱의 "기록과 공유" 가치와 충돌 가능.
>    - 기존 사용자가 `expShared=false`로 비공개 입력해온 경우 회귀가 발생함. 권장: 기본값만 `true`로 바꾸고 토글은 "고급 설정" 아코디언으로 접어두기. 완전 제거는 1주 사용 데이터 본 뒤 결정.

>    - 시각장애 접근성: 각 이모지 버튼에 `aria-label={c.label}` 추가.
