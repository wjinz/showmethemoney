## 5. 화면별 스펙

### 5.1 DiaryView (entry point)

레이아웃 순서(scroll 영역 위·아래 분리):

1. `view-header`: `우리 다이어리` + 오늘 날짜 서브.
2. `month-banner` (고정): 이번달 지출/예산/잔여.
3. `scroll-area`:
   - 오늘 내 입력 없음 → `today-prompt` 카드.
   - `groupByDate(diaries)` → `day-group` 반복.
   - 각 `day-label`은 `오늘/어제/날짜 + 지출합계(우측)` 구성.
   - 카드는 `DiaryCard`로 렌더.
4. Lightbox: 사진 클릭 시 풀스크린.
5. DetailSheet: 본인 카드 클릭 시 열림.

### 5.2 HistoryView

내부탭 토글(`innerTab: 'calendar' | 'report'`).

- **calendar**: `MiniCalendar` + 선택일의 `expense`·`diary` 블록 렌더. 파트너 지출은 총액+`세부 내역 비공개`.
- **report**: 월 요약 카드(ink 배경) + 주별 바차트(4주) + 부부별 지출 split + TOP3 지출일 + 무드 이모지 분포.

### 5.3 DashboardView

기존 위젯 중 **레이아웃 적합 6종만 유지**, 나머지는 §6 이관.

유지 목록: `AiNudge`, `BudgetRing`(couple-split 포함), 소비 페이스(진행률+예상지출), **내 지출 내역**(날짜 그룹+expand), 카테고리별 지출.

상단 우측에 `currentUser` 스위처(`husband`/`wife`) 배치. `onSetUser` 필수.

### 5.4 SettingsView

`월간 정산` 대형 카드 → `SettlementSheet` 오픈. 아래 리스트: 예산/고정/카드/보안/파트너/데이터초기화 + **이관 항목**(§6).

### 5.5 Input/Detail Sheet

- Mode 토글 `diary|expense`. 다이어리 저장 가드: `content.trim()` 필수. 지출 저장 가드: 유효 항목 1개 이상(`label` 있거나 `amount>0`).
- 숫자 파싱: `parseInt(String(x).replace(/[^0-9]/g,''))||0` 통일.
- 사진: `FileReader.readAsDataURL` → base64. 용량 방어: 단일 파일 5MB 초과 시 토스트 후 스킵.
- `shared` 토글: 지출 모드에선 "총액만 공유", 다이어리 모드에선 "내용 공유".

### 5.6 DiaryCard 프라이버시 규칙

```text
isMine = item.who === currentUser
- diary  + !isMine  → content 표시, photos/emoji 표시, shared=false면 숨김 처리
- expense + !isMine → content·expenseItems·photos 숨김, totalSpent만 + '세부 비공개'
- expense +  isMine → 전체 표시 + [수정] 핀
```

## 7. App.jsx 변경 (증분)

```js
const [view, setView] = useState('diary');
const [diaries, setDiaries] = useState(EMPTY_DIARIES);

const addDiary    = useCallback((d) => setDiaries(prev => [d, ...prev]), []);
const editDiary   = useCallback((upd) => setDiaries(prev => prev.map(x => x.id===upd.id?upd:x)), []);
const deleteDiary = useCallback((id) => setDiaries(prev => prev.filter(x => x.id!==id)), []);
```

## 9. 방어 코드 (Defensive Programming)

필수 시나리오별 방어.

1. `diaries === undefined` (첫 진입): 컴포넌트 진입부 `if (!Array.isArray(diaries)) return null;` 가드.
2. 날짜 파싱 실패: `new Date(date+'T00:00:00')` → `isNaN(getTime())` 체크 후 원본 문자열 폴백.
3. 파트너 역할 미확정: `currentUser` 폴백 `'husband'`.
4. 사진 base64 용량 초과(>2MB/장): 사용자 경고 후 스킵.
5. Supabase 오프라인: offlineQueue에 enqueue(`op:'upsert', key:'diaries'`) → 복구 시 flush.
6. 지출 항목 0개 저장 시도: 저장 버튼 `.45 opacity` + `return` 가드.

## 13. 리스크 & 트레이드오프

- **양대 스키마 공존(Tx↔Diary)**: 복잡성 증가. 완화책 — 모든 신규 입력은 DiaryItem, 조회 레이어에서만 병합.
- **사진 base64 크기**: 100KB 썸네일 제한 필요. 장기적으로 Supabase Storage 전환 고려(본 계획 범위 밖).
- **위젯 사용자 레이아웃 이전**: 기존 사용자의 `homeLayout`은 Dashboard로 포팅 전까지 설정 → `고급 대시보드`에서 열람 가능.

> [!CAUTION]
> **1. 치명적인 데이터 유실 위험 (InputSheet 누락 필드 & 마이그레이션)**
> - **이슈**: handoff-4 프로토타입의 지출 입력 시트(`InputSheet`)에는 `항목명`과 `금액`만 입력하게 되어 있습니다. 기존 가계부의 핵심인 `카테고리(cat)`, `결제 수단(payMethod)`, `카드 정보(cardId)`가 누락되어 있습니다. 이대로 구현하면 카테고리 통계와 카드 정산 기능이 **완전히 망가집니다.**
> - **해결책**:
>   1) **과거 데이터 마이그레이션 취소**: `TxItem`과 `DiaryItem`의 **`양대 스키마 완벽 공존(Dual Schema Coexistence)`** 전략을 채택하여, 렌더링 시점에만 `[...tx, ...diaries]`로 병합합니다.
>   2) **InputSheet 기능 보완**: 프로토타입의 UI 감성을 해치지 않는 선에서, 지출 입력 탭 하단에 `카테고리`와 `결제 수단/카드` 선택 UI를 반드시 추가하여 기존 기능을 100% 보존해야 합니다.

> [!WARNING]
> **2. Supabase Realtime 채널 크래시 위험 (사진 Base64)**
> - **이슈**: Supabase Realtime 채널과 JSONB 컬럼은 페이로드 제한이 있습니다. 5MB 원본 사진을 그대로 Base64로 인코딩하여 `household_data`에 저장할 경우 동기화 채널이 즉시 끊어지고 앱이 다운될 수 있습니다.
> - **해결책**: 브라우저 단에서 Canvas API를 활용해 사진을 업로드 직전 **최대 가로/세로 800px, WebP 포맷(Quality 0.6)**으로 강제 압축하여 장당 50KB 미만으로 리사이징하는 로직이 '필수' 방어 코드에 추가되어야 합니다.

> [!TIP]
> **3. 프라이버시 규칙 보완 (공용 지출의 본질)**
> - **이슈**: 계획상 파트너의 지출은 무조건 세부 내역을 숨기게 되어 있습니다 (`!isMine → content 숨김`). 하지만 가계부의 본질상 '공용 카드결제'나 '마트 장보기'는 부부가 함께 알아야 하는 내역입니다.
> - **해결책**: `DiaryItem`의 `shared` 플래그가 true인 지출에 대해서는 파트너에게도 '내용'과 '항목 내역'이 표시될 수 있도록 해야 합니다. UI 상의 '총액만 공유' 토글을 통해 사용자가 유연하게 프라이버시를 통제할 수 있게 합니다.

> [!NOTE]
> **4. 디자인 정합성 (Design Fidelity) 확인 완료**
> - handoff-4에 제시된 `DiaryView`(타임라인), `HistoryView`(달력/리포트), `DashboardView`(예산링/내 지출)의 레이아웃과 CSS 토큰(`--cream`, `--ink` 등)은 본 계획서의 컴포넌트 구조에 **100% 정확하게 매핑**되었습니다. 디자인 의도(감성적이고 미니멀한 UI)는 완벽히 유지됩니다.
