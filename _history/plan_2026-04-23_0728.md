# 단일 HTML → Vite 모듈형 복귀 및 기능 역이식 계획 (2026-04-23 07:28)

본 문서는 현재 프로덕션으로 배포된 단일 파일 구조(`index.html`)의 디자인과 사용자 경험을 100% 유지하면서, 기존 모듈형 코드베이스(`src/`)의 고급 기능(OCR, AI, 오프라인 큐 등)을 완벽하게 통합하기 위한 **옵션 B(Vite 복귀) 기반의 하이브리드 이식 상세 계획**입니다.

이 계획은 코드 에이전트가 교체되더라도 절대 누락이나 혼선이 발생하지 않도록, 실제 코드베이스 구조와 동작 방식을 깊이 있게 파악하여 작성되었습니다.

---

## 1. 현재 구조의 작동 방식 및 이해

### 1.1 `index.html` (현 프로덕션)의 작동 방식
현재 `index.html`은 CDN을 통해 React 18과 Babel Standalone을 브라우저에서 직접 파싱하여 실행되는 **단일 파일 애플리케이션**입니다.
- **상태 관리**: 전역 상태 관리자 없이 로컬 스토리지 키(`smtm_` 접두사, 예: `smtm_transactions`, `smtm_budget`)를 직접 읽고 쓰며 상태를 유지합니다.
- **UI 렌더링**: `HomeView`, `InputSheet`, `TxRow`, `MiniCalendar` 등 모든 컴포넌트가 하나의 파일 안에 인라인 스타일과 함께 작성되어 있습니다.
- **통신**: Supabase CDN 객체를 사용하여 Broadcast 채널(`sync_tx`)로 파트너 간 통신을 수행합니다. 데이터베이스 RDB에 직접 접근하지 않습니다.

### 1.2 `src/` (기존 모듈형)의 작동 방식
원래 개발되었던 `src/`는 Vite 기반의 모던 React 아키텍처입니다.
- **상태 관리**: `BudgetContext`를 통해 `tx`, `budgets`, `cards`, `fixed` 등의 전역 상태를 하향식으로 공급하며, 내부적으로 `offlineQueue` 및 `offlineIDB`를 거쳐 Supabase RDB로 동기화됩니다.
- **UI 렌더링**: `views/`, `components/`, `views/home-widgets/` 등 세분화된 폴더로 나뉘어 있으며, `react-grid-layout` 기반의 대시보드를 사용했습니다.
- **통신**: `postgres_changes` 기반의 강력한 실시간 동기화와 AI 모델 서버리스 API(`/api/*`)를 사용합니다.

---

## 2. 하이브리드 이식 핵심 전략 (Top-Down Design First)

가장 중요한 원칙은 **"현재 `index.html`의 레이아웃과 형태를 절대 훼손하지 않는다"**는 것입니다. 따라서 기존 `src/`의 컴포넌트 껍데기를 살리는 것이 아니라, `index.html`의 JSX 껍데기를 뜯어내어 `src/`에 덮어씌우고 그 안에 로직을 주입합니다.

### 🔴 중요 규칙 (에이전트 인계 시 필독)
1. **디자인 무결성**: 3가지 테마 시스템(Dark/Light/Oldschool)은 폐기되었으며 구현하지 않습니다. 현재 `index.html`의 CSS와 인라인 스타일 형태를 그대로 유지합니다.
2. **Gemma 4 비용 최적화**: API 연동 시 Gemma 4 등 경량 모델을 사용하는 것은 오직 **"토큰 및 호출 비용을 절감하기 위함"**입니다. 성능 개선을 핑계로 고비용 모델로 임의 변경해서는 안 됩니다.
3. **네임스페이스 표준화**: 상태 관리 키는 `index.html`에서 정립한 `smtm_*` 네이밍을 표준으로 채택하여 하위 호환성을 보장합니다.

## 3. 단계별 상세 마이그레이션 계획

### M1 — 구조 결정 및 사전 준비 (0.5일)
Vite 복귀(옵션 B)를 확정하고, 상태 관리 매핑을 준비합니다.

- **작업 내용**:
  1. `smtm_*` ↔ `BudgetContext` 상태 매핑표 확정 및 동결.
  2. `smtm_budget` (단일 총액)을 `budgets` 9개 카테고리로 쪼개는 마이그레이션 스크립트 작성.
  3. `index.html`에 있는 CSS 인라인 스타일을 `src/index.css`로 이관하여 디자인 무결성 준비.

### M2 — 본질 복원 P0 및 뼈대 이식 (2~3일)
가계부의 본질적 결손을 해결하고 껍데기(UI)를 이식합니다.

- **작업 내용**:
  1. **디자인 이식**: `index.html`의 뷰 컴포넌트(`HomeView`, `InputSheet`, `TxRow` 등)를 `src/`로 이동. `src/views/HomeView.jsx`의 `react-grid-layout` 로직을 폐기하고 `index.html` 코드로 완전 대체.
  2. **OCR 연동**: 단일/벌크 영수증 스캔 및 `ReceiptSplitter`, `useOcrScan` 기능 활성화.
  3. **블라인드 로직**: `is_private` 플래그 적용 및 `blindPartnerTx` 유틸리티 연동.
  4. **SOS RDB 연동**: 기존 `sos_requests` 테이블 RDB 저장 및 트리거 방식(`trg_sos_approved`)으로 승격.
  5. 할부(`InstallItem`) 및 카드 결제주기 기능 복원.

- **코드 스니펫 (예시: `src/views/HomeView.jsx` 개편)**:
  ```jsx
  // src/views/HomeView.jsx
  import React, { useState } from 'react';
  import { BudgetRing, AllowanceCard, MiniCalendar, TxRow } from '../components';
  import { useBudget } from '../context/BudgetContext';

  export function HomeView({ onNav }) {
    const { tx, budget, names } = useBudget(); 
    // index.html의 로직 복사 후 UI 유지
    return (
      <div className="view-content" style={{ padding:'0 16px' }}>
        <AllowanceCard transactions={tx} onNav={onNav} />
        <MiniCalendar transactions={tx} />
      </div>
    );
  }
  ```

### M3 — 고부가가치 P1 (2일)
`src/`에만 존재하던 핵심 부가 기능들을 통합합니다.

- **작업 내용**:
  1. **AI 3종 연동**: Nudge(KV 캐시 사용), Budget, Kids Coach 기능 복원. (비용 문제로 Gemma 4 모델 파이프라인 강제 유지).
  2. **Plan 탭 복원**: 연간 이벤트, 목표, 저축 타깃 설정.
  3. **특수 뷰 이식**: Asset(자산 관리) 및 Tax(연말정산 최적화) 뷰 복원.
  4. **Kids Mode 전체 복원**: 돼지저금통 게이지 및 미션 시스템 복구.

### M4 — 안정성 P2 (1~2일)
데이터 무결성 및 시스템 안정성을 확보합니다.

- **작업 내용**:
  1. **오프라인 큐 고도화**: `offlineQueue`(localStorage) + `offlineIDB`(IndexedDB) 병렬 동기화, 디바운스(tx 300ms, 기타 800ms) 및 지수 백오프 로직 복구.
  2. **Realtime 강화**: Broadcast 채널을 넘어 DB 단의 `postgres_changes` 기반 실시간 동기화로 복귀.
  3. **관리자 기능**: Admin 뷰 및 BugReport 기능 복원.
  4. **Data Import**: SheetJS를 이용한 xlsx 데이터 가져오기 기능(`DataImportView`) 복구.

### M5 — UX 고도화 P3 (1.5일)
디테일한 사용자 경험 요소를 추가합니다. (테마/위젯 시스템은 폐기)

- **작업 내용**:
  1. **PWA 최적화**: manifest 연동, Service Worker, Share Target 연동 완료.
  2. **입력 편의성**: `QuickEntrySheet` (빠른 입력 칩, FrequentPattern) 및 `ScheduleScanSheet` (근무표 스캔) 로직 이식.

### M6 — 회귀 검증 (0.5일)
- **작업 내용**:
  1. 크로스 디바이스 간 Realtime 동기화 정상 작동 테스트.
  2. 오프라인에서 지출 입력 후 온라인 복귀 시 정상 Flush 되는지 확인.
  3. iOS Safari / Android Chrome PWA 설치 여부 점검.
  4. OCR 429 에러 핸들링 및 AI Nudge KV 캐시 히트 검증.
