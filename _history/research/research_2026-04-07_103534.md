# 프로젝트 심층 분석 보고서 (2026-04-07 10:35)

## 1. 프로젝트 아키텍처 및 코어 작동 원리
본 프로젝트 `family-budget-app`은 **React (Vite) + Supabase + Vercel Serverless** 기반으로 구축된 가족/파트너용 실시간 가계부 솔루션입니다. 

1. **프론트엔드 (React + Vite)**
   - PWA(Progressive Web App)를 지원해 Web Share Target API를 통해 영수증 및 문자를 곧바로 앱으로 넘겨받을 수 있습니다.
   - `react-grid-layout`을 사용하여 커스텀 가능한 모듈형 위젯 기반의 홈 대시보드 구조를 지니고 있습니다.
   > 💡 **[Antigravity의 의견] 렌더링 최적화:** 현재 `BudgetContext`를 통해 전체 상태관리를 수행하므로, 잦은 트랜잭션 업데이트 시 앱 전체가 리렌더링될 수 있습니다. `Zustand`나 `Jotai` 같은 아토믹/스토어 기반 상태 관리 라이브러리를 도입하고, `React.lazy`로 컴포넌트를 분할 로딩하면 체감 성능이 대폭 향상될 것입니다.
2. **글로벌 상태 관리 및 동기화 (`BudgetContext` / `offlineQueue.js`)**
   - 데이터 변경 시 Supabase의 Realtime 채널을 통해 즉시 파트너(Husband/Wife) 기기에 양방향 동기화 처리됩니다.
   - 오프라인 시 조작한 데이터는 로컬 큐에 보존했다가 재연결 시 `offlineQueue.js`를 통해 일괄 동기화(Flush)됩니다.
   > 💡 **[Antigravity의 의견] 더 강력한 오프라인 동기화 보장:** PWA의 Service Worker 내 `Background Sync API`를 연동하면, 앱이 닫히거나 백그라운드에 있을 때 네트워크가 복구되어도 자동으로 시스템단에서 안전하게 동기화를 수행해 데이터 유실을 더욱 완벽히 차단할 수 있습니다.
3. **서버리스 AI 백엔드 (Vercel Functions + Gemini 2.5 Flash)**
   - `api/` 폴더에 위치한 서버리스 함수들이 Vercel에 의해 호스팅됩니다.
   - `ocr.js`: 카카오/토스 등에서 캡처된 카드 내역 이미지와 영수증 이미지를 정밀 분석. 
   - `budget-ai.js`, `nudge.js`: 유저의 소비 내역, 급여 등을 분석해 잔여 예산 대비 AI 코칭 팁과 카테고리별 예산을 1만원 단위로 자동 배분해줍니다.
   > 💡 **[Antigravity의 의견] AI 응답 캐싱 및 예외 처리:** 빈번하게 동일한 파라미터(예: 같은 급여, 고정비 설정)로 호출되는 AI 함수 호출 결과를 Vercel KV나 Redis에 일정 시간 캐싱하면 응답 속도를 높이고 API 비용을 크게 절감할 수 있습니다. 또한 Gemini API 오류 시를 대비한 로컬 기본 배분 알고리즘(Fallback) 강화도 좋은 보험이 될 것입니다.
4. **데이터베이스 구조 (`supabase.js`)**
   - 기존의 `household_data`를 통한 K-V 방식을 넘어 확장형 `transactions` 테이블, `sos_requests`(파트너 간 가불 승인 처리 테이블) 등 RDB의 특성을 살리는 방식으로의 전환 로직이 포함되어 있습니다.
   > 💡 **[Antigravity의 의견] 철저한 데이터 무결성 및 RLS 적용:** RDB로 점진적 고도화를 진행 중인 만큼, `transactions` 및 `sos_requests` 테이블에 Supabase Row Level Security(RLS) 정책을 엄격히 설정하여, 인증된 사용자라도 자신이 속한 `household_id` 외의 데이터에는 절대 접근할 수 없도록 강제하는 것이 보안의 핵심입니다.

## 2. 주요 기능 및 디렉토리 구성
- **`src/views/`**: `HomeView` (위젯 대시보드), `PrivateWalletView` (비상금/개인 지갑 관리), `DashboardView` 등의 메인 프레젠테이션.
- **`src/components/`**: `CardScanSheet.jsx` (OCR 연동 영수증 스플리터 등), `TxEditModal.jsx`, `InputModal.jsx`, 바텀 시트 기반의 최신 UI/UX 요소 집합.
- **`src/styles/`**: Vanilla CSS 바탕의 고성능 커스텀 디자인 시스템 (`theme.css`). 다크 모드, 개인 모드에 따른 동적 팔레트.
- **`src/utils/`**: 데이터 검증, 지연 저장(debounce), 오프라인 큐 등을 통한 안정성 보장.

## 4. 폴더 정리를 위한 가이드 (터미널 및 컨텍스트 정리)
현재 프로젝트 내부에는 방대한 양의 히스토리와 중복 폴더가 존재하여, **검색 속도 저하, LLM 토큰 낭비, 및 터미널의 원활한 운영을 방해**하고 있습니다. 코드베이스 깔끔한 유지를 위해 3단계 정리를 권장합니다.

**✅ 1단계: 중복 프로젝트(`budget-v2`) 제거 혹은 분리**
- 현재 루트 하위에 완전히 동일한 구조(`src/`, `api/`, `package.json` 등)를 가진 `budget-v2/` 디렉터리가 통째로 존재합니다.
- 작동에 혼란을 초래하므로 이 폴더는 프로젝트 경로 바깥(예: 데스크탑 혹은 휴지통)으로 옮기거나 삭제를 권장합니다.
- *명령어 예시*: `mv "budget-v2" ../budget-v2-backup`

**✅ 2단계: `archive` 및 불필요 마크다운 파일들의 격리 보관**
- `archive/` 폴더 내 수많은 압축 파일(`*.zip`), 이전 분석 결과(`CODE_ANALYSIS*.md`), 및 과거 계획서들이 용량 및 LLM 인덱싱 낭비를 유발 중입니다.
- 프로젝트 최상단에 있는 `HANDOVER_V3.md`, 과거 날짜가 적힌 `research_*.md` 등과 함께 `archive/` 디렉터리를 외부로 이동하거나 GitHub Release 등에 백업하고 지우십시오.
- *정리 방법*: 현재 활성화된 지침서(`README.md` 등) 한두 개만 남기고 모든 마크다운을 `.obsidian` 같은 문서화 전용 앱이나 별도 스토리지로 보관.

**✅ 3단계: 필수 폴더 구조 표준화**
추후 작업 시 아래와 같이 컴팩트한 루트를 유지하십시오.
```text
📦 어플개발_우진지연 budget
 ┣ 📂 api/                (Vercel 서버리스 폴더)
 ┣ 📂 src/                (실제 소스코드)
 ┣ 📂 public/             (아이콘, 정적 에셋)
 ┣ 📜 package.json
 ┣ 📜 vite.config.js
 ┣ 📜 vercel.json
 ┗ 📜 README.md           (이 외 과거 산출물 마크다운은 제거)
```
이렇게 폴더를 유지하면 터미널에서의 파일 검색 및 자동화 작업(AI, grep 등)이 훨씬 정확하고 쾌적하게 동작합니다.
