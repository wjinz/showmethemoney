## 1. 프로젝트 개요

**ShowMeTheMoney**는 부부가 함께 사용하는 모바일 우선 PWA 가계부 앱이다. 6자리 가정 코드로 실시간 데이터를 공유하며, AI 기반 OCR, 예산 추천, 소비 코칭 기능을 탑재하고 있다. Vercel에 배포되어 있으며 프로덕션 URL은 `https://showmethemoney-eta.vercel.app`이다.

### 기술 스택

| 영역 | 기술 |
|---|---|
| 프론트엔드 | React 18 + Vite 5 |
| 상태관리 | React Context (BudgetContext) + Zustand (kidsStore) |
| 백엔드 DB | Supabase (PostgreSQL) |
| 서버리스 API | Vercel Serverless Functions (4개) |
| AI 엔진 | Google Gemini (gemini-2.5-flash, gemma-4-31b-it) |
| 캐시 | Vercel KV (Redis) |
| 애니메이션 | framer-motion |
| 차트 | Recharts |
| 레이아웃 | react-grid-layout (드래그 가능 위젯) |
| 오프라인 | Service Worker + IndexedDB + localStorage |
| 날짜 유틸 | date-fns |
| 배포 | Vercel (production) |

## 3. 핵심 데이터 모델

### 3.1 Supabase 테이블 구조

**household_data** (핵심 KV 스토어)

모든 가계부 데이터는 `household_data` 테이블에 JSONB 방식으로 저장된다. 각 row는 `{id: 가정코드, key: 데이터종류, value: JSONB}` 형태다.

| key | 내용 |
|---|---|
| `tx_YYYY` | 연도별 거래 내역 배열 (예: `tx_2026`) |
| `fixed` | 고정비 목록 |
| `install` | 할부 목록 |
| `cards` | 카드 목록 |
| `settlements` | 카드 정산 기록 |
| `assets` | 자산 목록 |
| `budgets` | 카테고리별 월 예산 |
| `names` | 부부 이름 (`{husband, wife}`) |
| `plan` | 연간 재무 계획 (급여, 저축목표, 이벤트, 목표) |
| `taxConfig` | 연말정산 설정 |
| `widgetLayout` | 위젯 드래그 레이아웃 |
| `homeLayout` | 홈 위젯 레이아웃 |
| `kidsMode` | 아이 모드 활성 여부 |
| `diaries` | 부부 다이어리 목록 (v7 신규) |

**transactions** (RDB 정규화 테이블 — 마이그레이션 예정)

현재는 `tx_YYYY` JSONB 방식이지만, 트랜잭션 무결성 강화를 위해 정규화 테이블로 이전할 계획이 있다. `kid_id` 외래키 컬럼이 이미 추가되어 있다.

**kids_profiles / kids_missions** (아이 전용)

RLS(Row Level Security) 정책이 적용되어 있고 `app.household_id` 세션 설정 기반으로 격리된다. `increment_kid_savings`, `complete_and_reward_mission` RPC 함수로 저금통 로직을 처리한다.

**sos_requests** (긴급 송금 요청)

부부 간 긴급 자금 요청 시스템. `requester`, `amount`, `reason`, `repay_plan`, `status` 필드를 가진다.

### 3.2 주요 타입 정의 (TxItem)

```js
{
  id: number,
  date: string,          // 'YYYY-MM-DD'
  amount: number,        // 원화
  cat: string,           // 9개 카테고리 중 하나
  memo: string,
  who: string,           // 'husband' | 'wife'
  payMethod: string,     // 'credit' | 'debit' | 'cash'
  type?: string,
  cardId?: string,
  is_private?: boolean,  // 개인 지갑 여부
  kid_id?: string        // 아이 연결 지출
}
```

### 3.3 카테고리 시스템 (9종)

`food`, `housing`, `education`, `transport`, `medical`, `culture`, `clothing`, `sub`, `etc`
각 카테고리는 아이콘, 색상, 기본 예산값을 가진다.

## 4. 앱 아키텍처 흐름

### 4.1 초기화 흐름

```
앱 진입
  → lsMigrateLegacy() — 레거시 localStorage 키 smtm_ prefix로 마이그레이션
  → lsGet(HOUSEHOLD_ID) — 저장된 가정 코드 확인
  → 없으면 SyncSetup 온보딩 화면 (생성/참여)
  → 있으면 loadShared(hid) — Supabase에서 모든 데이터 로드
  → 현재 연도 tx만 우선 로드 (성능 최적화)
  → Supabase Realtime 구독 시작 (postgres_changes)
  → 오프라인 큐 플러시 시도
  → 앱 정상 진입
```

### 4.2 상태 관리 전략 (3계층)

**1계층 — App.jsx 로컬 상태**
공유 데이터(tx, fixed, install, cards, settlements, assets, plan, budgets, names, taxConfig, diaries)와 UI 상태(view, modal, theme)를 모두 App.jsx에 집중 관리한다.

**2계층 — BudgetContext**
prop drilling 제거 목적. App.jsx에서 주입, 하위 컴포넌트에서 `useBudget()`으로 소비한다. 점진적 전환 전략 — 기존 View는 props 유지, 신규 컴포넌트부터 Context 사용.

**3계층 — Zustand (kidsStore)**
Kids 전용 상태를 격리. `kidsProfiles`, `kidsMissions`를 별도 스토어로 관리해 불필요한 리렌더링을 방지한다.

### 4.3 저장 흐름 (데이터 쓰기)

```
사용자 입력
  → 낙관적 업데이트 (즉시 로컬 상태 반영)
  → debounce 타이머 시작 (중복 저장 방지)
  → 온라인: db.save(hid, key, value) → Supabase upsert
  → 오프라인: enqueue(key, value) → localStorage 큐
            + idbEnqueue() → IndexedDB 큐 (Background Sync용)
  → 온라인 복구 시: flush() → 큐 일괄 재전송
                   또는 SW Background Sync 이벤트로 자동 플러시
```

### 4.4 tx 연도별 분리 로딩 (Lazy Loading)

거래 내역이 많아질 경우를 대비해 연도별로 분리 저장한다. 현재 연도만 초기 로드하고, 다른 연도는 해당 연도 화면 진입 시 `loadTxYear(year)`로 지연 로드한다. 레거시 `tx` 키가 존재하면 자동으로 `tx_YYYY` 키로 마이그레이션한다.

### 4.5 실시간 동기화

Supabase Realtime의 `postgres_changes` 이벤트를 구독한다. `household_data` 테이블의 INSERT/UPDATE를 감지해 파트너 기기에 즉시 반영된다. `updateSharedState(key, value)` 함수가 수신 변경을 라우팅한다.

## 6. AI 기능 상세

모든 AI 호출은 Vercel Serverless Function을 통해 서버 사이드에서 이루어진다. API 키(GOOGLE_API_KEY)는 환경 변수로만 관리되어 브라우저에 노출되지 않는다. `x-internal-secret` 헤더로 직접 외부 호출을 차단한다.

### 6.1 OCR — `/api/ocr.js`

- **모드 2종**: `single`(영수증 단건) / `bulk`(카드 앱 스크린샷 다건)
- **전처리**: Canvas API로 리사이즈 + 모드별 필터
  - single: 480px + 흑백 이진화 (대비 1.4, 임계값 160)
  - bulk: 1200px + 컬러 보존 (다크모드 앱 인식률 유지)
  - WebP/JPEG 0.8 압축으로 전송량 50~70% 절감
- **방어 로직**: AI 파싱 실패 시 `extractBulkItemsFallback`이 정규식으로 유효 항목 추출
- **날짜 변환**: "오늘/어제/04-15/26. 4. 12(일)" 등 한국 다양한 포맷 처리
- **필터**: 거래취소, 가승인, 음수 금액 자동 제외

### 6.2 AI 예산 배분 — `/api/budget-ai.js`

- **모델**: `gemini-2.5-flash`
- **입력**: 급여, 고정비, 할부, 저축목표, 최근 카테고리별 지출 현황
- **출력**: 9개 카테고리별 추천 예산 + 이유 + 팁
- **캐시**: Vercel KV, 상위 2개 카테고리 기반 캐시 키
- **폴백**: API 실패 시 하드코딩 비율로 로컬 계산
- **클라이언트 폴백** (BudgetView): `runLocalAI()` — 과거 60% + 표준 가이드 40% 가중치

### 6.3 AI 소비 코칭 — `/api/nudge.js`

- **모델**: `gemma-4-31b-it` (1순위) → `gemini-2.5-flash-lite` (폴백)
- **캐릭터**: 까칠하지만 츤데레인 가계부 AI
- **예산 소진율 분기**: 90%↑ 잔소리 / 50%↓ 응원
- **출력**: 40자 이내 한 문장
- **캐시**: pct 5% 단위 버킷 + 월 기준, TTL 24시간

### 6.4 아이 응원 코치 — `/api/kids-coach.js`

- **모델**: `gemini-2.5-flash`
- **대상**: 5~8세 아이 눈높이
- **출력**: 20자 이내 + 이모지 1개
- **캐시**: pct 5% 버킷, TTL 30분

## 7. 오프라인 지원 아키텍처

### 7.1 이중 큐 시스템

**localStorage 큐** (`offlineQueue.js`): 동일 key 최신값 덮어쓰기, 온라인 복구 시 `flush()` 일괄 재전송.

**IndexedDB 큐** (`offlineIDB.js`): Service Worker가 직접 접근 가능. `budget-offline-db/queue` 스토어. IDB 버전 관리 포함.

### 7.2 Service Worker (`public/sw.js`)

- **설치**: `/`, `/index.html` 선캐싱
- **활성화**: 구버전 캐시 정리, `clients.claim()`
- **Background Sync**: `offline-queue-flush` 태그로 IndexedDB 큐를 Supabase REST API에 직접 재전송. Supabase 환경 변수는 vite.config.js `define`으로 빌드 타임 주입됨.

## 10. 프로젝트 이중 구조 문제

현재 두 개의 독립 코드베이스가 공존한다.

**`src/` (모듈형 React — 개발 베이스)**:
Vite 빌드, 완전한 기능. 19개 뷰, 4개 AI 연동, 위젯 시스템, Kids/SOS/다이어리 모두 구현됨.

**`index.html` (레거시 단일 HTML)**:
CDN React + Babel Standalone. OCR, Kids, Admin, 자산/세금/할부/데이터임포트 미이식 또는 placeholder. 저장소 키 호환 불가(smtm_budget 단일 숫자 vs 카테고리별 9종).

Vercel은 `dist/` 빌드 산출물을 배포한다. `_archive/builds/` 하위에 과거 빌드 다수 존재.

부부 공유(6자리 코드, Supabase Realtime), 지출 입력(직접+OCR+bulk 스캔), 고정비/할부/카드 관리, 카테고리 예산, 카드 정산 계산기, AI 소비 코칭(nudge), AI 예산 배분, 아이 저금통(KidsView+kidsStore), 개인 지갑+SOS 요청, 연말정산 최적화 가이드, 엑셀 임포트, 3가지 테마, 오프라인 이중 큐+SW Background Sync, react-grid-layout 위젯 대시보드, PWA(홈 설치+Share Target), 버그 리포트 저장.

## 14. 핵심 유틸리티 요약

| 파일 | 역할 |
|---|---|
| `utils/supabase.js` | Supabase 클라이언트 + db 헬퍼 (loadAll, loadTx, saveTx, save, loadKids 등) |
| `utils/offlineQueue.js` | localStorage 오프라인 큐 (enqueue/flush/hasTxQueued) |
| `utils/offlineIDB.js` | IndexedDB 오프라인 큐 (idbEnqueue/idbDequeueAll/idbRemove) |
| `utils/ls.js` | localStorage 네임스페이스 헬퍼 (`smtm_` prefix) + 레거시 마이그레이션 |
| `utils/ocr.js` | 이미지 전처리 + `/api/ocr` 호출 래퍼 |
| `utils/helpers.js` | 날짜/금액 포맷(fmt/fmtS/fmtC), 카드 청구 기간 계산(getBillingPeriod) |
| `utils/validate.js` | 지출 입력 유효성 검사 |
| `styles/theme.css` | CSS 변수 테마 정의 (light/dark/oldschool) |
| `constants/index.js` | 카테고리, 기본 예산, 타입 정의, LS 키, 빈 배열 상수 |
