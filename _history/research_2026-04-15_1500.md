## 1. 프로젝트 개요

부부(또는 솔로)를 위한 **클라우드 동기화 가계부 PWA**. React + Supabase 기반으로 두 기기에서 실시간으로 데이터를 공유하며, Vercel Serverless Function을 통해 Gemini AI 기능을 제공한다. 아이 용돈 관리(Kids Mode), SOS 가불 시스템, 카드 명세서 OCR 등 다수의 고급 기능을 갖추고 있다.

## 6. 동기화 및 오프라인 처리 흐름

```
사용자 액션
    │
    ▼
setShared(key, value)
    │
    ├─ 낙관적 UI 업데이트 (즉시 반영)
    ├─ validate(key, value)  -- 스키마 검증 (경고만)
    │
    ├─ [오프라인]
    │   └─ offlineQueue.enqueue() → localStorage 저장
    │
    └─ [온라인]
        └─ db.save() / db.saveTx()  (지수 백오프, 최대 3회)
              │
              ├─ 성공: setSyncStatus("ok")
              └─ 실패: offlineQueue.enqueue() + setSyncStatus("error")

온라인 복구 이벤트 (window 'online')
    └─ flushOfflineQueue() + flushTxQueue() → Supabase 재전송

Background Sync (Service Worker)
    └─ IndexedDB(offlineIDB) → Supabase REST API 직접 호출
        (SyncManager 지원 브라우저 한정)
```

### tx 저장 최적화 (디바운스 + 연도별 분리)

- `setTx`는 `txDirty.current = true`만 설정 (즉시 저장 안 함)
- useEffect가 300ms 디바운스 후 연도별로 분리하여 `db.saveTx(hid, year, rows)` 호출
- `loadedTxYears`에 있는 연도만 저장 (미로드 연도 덮어쓰기 방지)
- 과거 연도 tx는 `loadTxYear(year)` 호출 시 Lazy Loading

### 실시간 구독 (Supabase Realtime)

`db.subscribe(hid, callback)` — `household_data` 테이블의 INSERT/UPDATE/DELETE 이벤트를 구독하여 파트너 기기의 변경사항 즉시 반영. 채널 중복 방지를 위해 `_channels` Map 관리.

SOS 채널은 별도로 `db.subscribeSos(hid, callback)`으로 구독.

## 9. AI 기능 상세

### 9-1. OCR (api/ocr.js)

영수증 또는 카드 명세 스크린샷을 Gemini AI로 분석. 3가지 모드:
- `single` — 영수증 1건 (amount, cat, memo)
- `bulk` — 카드앱 이용내역 다건 추출 (배열 반환)
- `schedule` — 근무 스케줄표 파싱 (이름/날짜/타입)

폴백 모델 체인: Gemma 4 31B → Gemini 2.5 Flash → Gemini 2.0 Flash (429/503 시 자동 전환)

클라이언트 최적화 (`src/utils/ocr.js`):
- 이미지 리사이즈 (single: 800px, bulk/schedule: 1536px)
- 흑백 변환으로 데이터 크기 감소
- sessionStorage LRU 캐시 (최대 5개)
- 429 응답 시 30초 쿨다운

### 9-2. AI 예산 배분 (api/budget-ai.js)

급여, 고정비, 저축 목표, 최근 3개월 지출 패턴을 기반으로 9개 카테고리 예산 추천.
- Gemini 2.5 Flash 사용
- Vercel KV 캐시 (TTL 24시간)
- 캐시 키: `budget:{급여}:{고정비}:{상위2카테고리}:{월}`
- Gemini 실패 시 로컬 규칙 기반 폴백 (`DEFAULT_RATIOS` 비율 적용)

### 9-3. AI Nudge (api/nudge.js)

예산 소진율에 따라 "까칠한 츤데레" 톤의 단문 메시지 생성.
- 모델: Gemma 4 31B → Gemini 2.5 Flash Lite (폴백)
- pct 5% 단위 버킷팅으로 캐시 히트율 향상
- Vercel KV 캐시 (TTL 24시간)

### 9-4. Kids Coach (api/kids-coach.js)

아이 달성률에 따른 응원 메시지 (20자 이내, 이모지 포함).

## 10. PWA 및 Service Worker

**manifest.json** 핵심 설정:
- `display: standalone` — 네이티브 앱처럼 동작
- `theme_color: #c8a84b` (골드)
- **Share Target**: 타 앱에서 이미지/텍스트 공유 수신 (`/share-handler` POST)

**sw.js** 기능:
1. 설치 시 `/`, `/index.html` 선캐싱
2. 구버전 캐시 자동 정리
3. **Background Sync**: `offline-queue-flush` 태그로 IndexedDB 큐를 Supabase REST에 직접 전송
4. **Share Target 처리**: 공유된 이미지/텍스트를 열린 앱 탭에 `postMessage`로 전달
5. GET 요청 Cache-First (Supabase/API 제외)

> [!TIP]
> **Antigravity 추가 분석 (Share Target 동작):**
> - `App.jsx`에서 `sw-share` 커스텀 이벤트를 구독하여 데이터를 수신합니다.
> - **이미지 공유:** `window.__sharedFile`에 저장 후 `CardScanSheet`가 자동 실행됩니다.
> - **텍스트 공유:** `window.__sharedText`에 담아 `QuickEntrySheet`가 열리며 텍스트 파싱을 준비합니다.

## 11. 인증 및 보안

- **가계부 코드**: 6자리 alphanumeric 랜덤 코드 (`Math.random().toString(36).slice(2,8).toUpperCase()`)가 가계부 ID 역할. 코드를 알면 접속 가능한 구조 (비밀번호 없음).
- **Row Level Security (RLS)**: Supabase 테이블에 RLS 적용. `current_setting('app.household_id')` 기반 정책으로 자기 가계부 데이터만 접근.
- **Serverless API 보호**: `INTERNAL_API_SECRET` 환경변수를 통해 프런트엔드 외 외부 요청 차단 (`x-internal-secret` 헤더 검증).
- **관리자 모드**: 숨겨진 클릭 트리거(5회)로 진입, localStorage에 `isAdmin` 저장.
- **개인 지출 블라인드**: `is_private=true` 거래는 배우자에게 "용돈 대체: X원"으로 표시.

## 12. 테마 시스템

**3가지 테마 모드** (`data-color-scheme`):
- `dark` (기본) — 다크 모드
- `light` — 라이트 모드

**3가지 컨텍스트 테마** (`data-theme`):
- `joint` — 부부 공유 모드 (기본, 골드 계열)
- `private` — 개인 지갑 뷰 (보라/그린 계열)
- `kids` — 아이 모드 (밝고 채도 높은 계열)

`useTheme(view, kidsMode)` 훅이 `data-theme` 속성을 자동 전환. `theme.css`에서 CSS 변수로 실제 색상 정의. `tokens.js`에서 spacing/radius/shadow/font 토큰 중앙 관리.

## 13. 주요 데이터 마이그레이션 로직

앱 초기화(`loadShared`) 시 하위 호환성을 위한 자동 마이그레이션이 실행된다.

1. **tx 연도별 분리**: 레거시 `tx` 키 → `tx_2024`, `tx_2025` 등으로 분리 후 레거시 키 비우기
2. **card.name → card.label**: 구버전 카드 데이터 필드명 정규화
3. **plan.monthlyIncome → plan.salary**: 급여 구조 변경 (단일값 → `{husband, wife}` 객체)
4. **homeLayout 위젯 교체**: 구버전 `progress_ring`, `summary_bars`, `scan_banner` → `execution_summary`로 통합
5. **household_data → transactions 마이그레이션**: `tx_YYYY` JSON → `transactions` RDB 테이블 일괄 insert (1회성 플래그 `migrated_to_rdb`)

> [!IMPORTANT]
> **Antigravity 추가 분석:**
> - 마이그레이션은 `loadShared` 함수 내에서 순차적으로 실행되며, 원자적(Atomic)이지 않을 수 있으므로 실패 시 재시도 로직이 중요합니다.
> - `migrated_to_rdb` 플래그는 RDB 전환을 위한 과도기적 단계로, 현재는 KV 저장소와 RDB가 병행 업데이트되지 않고 1회성 마이그레이션만 수행되고 있음에 유의해야 합니다.

## 14. SOS 가불 시스템

파트너에게 개인 용돈 가불을 요청하는 기능.

흐름:
1. 요청자: `SosRequestSheet` → `db.createSosRequest()` → `sos_requests` INSERT
2. 상대방: Supabase Realtime으로 즉시 수신 → `SosPendingSheet` 팝업 → 승인/거절
3. 승인 시: `db.resolveSos(id, 'approved')` → SQL 트리거 `trg_sos_approved`가 `transactions` 테이블에 자동 INSERT

HomeView의 `HomeSosPendingWidget`이 pending 건수를 배지로 표시.

## 15. 카드 관리 및 결제 주기 계산

`CardItem`에 `billingStartDay`, `billingEndDay`, `billingEndNextMonth`, `paymentDay` 필드 저장.

`getBillingPeriod(card, today)` 함수가 현재 날짜 기준으로 현재 청구 주기(`cycleStart`, `cycleEnd`)와 결제일(`payDate`), D-day(`daysUntilPay`)를 계산.

## 16. 발견된 특이사항 및 기술 부채

1. **이중 저장 구조**: `household_data`(JSONB KV)와 `transactions`(정규화 RDB)가 병존. 현재 조회는 KV에서, 마이그레이션 목적으로만 RDB insert. 향후 RDB 전환 준비 중으로 보임.

2. **RLS 정책 방식**: `current_setting('app.household_id')`를 사용하는데, 이 설정은 클라이언트에서 `supabase.rpc()` 등으로 세션 변수를 set해야 동작함. anon key 사용 시 이 정책이 실제로 작동하는지 확인 필요.

3. **관리자 인증 취약**: localStorage에 `isAdmin: true`를 저장하는 방식으로, 개발자 도구로 쉽게 우회 가능.

4. **tx Functional Update 패턴**: `B1 fix`로 명시된 대로, 연속 추가 시 stale closure를 방지하기 위해 `setTx`에 functional update를 사용. `addTxBatch`로 벌크 추가 시 race condition 완전 방지.

5. **KidsView 단일 아이 지원**: 현재 `kidsProfiles[0]`만 사용. 다중 아이 지원은 미구현.

6. **API 인증 방식**: Vercel KV(`@vercel/kv`)를 캐시로 사용하는데, 이는 Vercel 환경에서만 동작하므로 로컬 개발 시 KV 캐시 없이 동작.

7. **스타일 일관성**: `tokens.js` 도입으로 토큰화를 시작했으나, 기존 코드는 인라인 스타일 하드코딩이 많아 점진적 전환 중.

## 19. Antigravity 최종 리뷰 및 제언

**전반적인 평가:** 이 프로젝트는 PWA와 서버less 환경을 극한으로 활용한 높은 완성도의 모던 웹 애플리케이션입니다. 특히 오프라인 지원(Background Sync, Offline Queue)과 실시간 동기화(Supabase Realtime)의 조합이 매우 견고하게 설계되었습니다.

**주요 강점:**
- **복제 및 동기화:** `txDirty.current`와 디바운스 메커니즘을 통한 연도별 tx 저장 최적화가 우수합니다.
- **사용자 경험:** Share Target을 통해 외부 앱의 영수증 이미지를 즉시 처리하는 흐름은 매우 사용자 친화적입니다.
- **확장성:** Kids Mode와 SOS 시스템이 독립적인 테이블 및 채널로 분리되어 있어 향후 기능 확장이 용이합니다.

**개선 권고:**
- **데이터 일관성:** 현재 KV(JSONB)와 RDB(transactions)가 공존하는데, `insertTx`가 성공하더라도 KV 저장이 실패하거나 그 반대의 경우 데이터 불일치가 발생할 수 있습니다. 트랜잭션 처리가 필요해 보입니다.
- **인증 보안:** 보고서에서도 언급되었듯 `isAdmin`의 로컬 저장 방식은 보안에 취약합니다. 관리 권한이 필요한 API 호출 시 서버측 검증이 필수적입니다.
- **다중 아이 지원:** `KidsView`가 `kidsProfiles[0]`에 고정되어 있으므로, 프로필 선택 UI 추가가 필요합니다.
