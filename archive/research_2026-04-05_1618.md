## 1. 프로젝트 개요 및 아키텍처
본 프로젝트는 부부(Husband/Wife)가 함께 사용하는 공유 가계부 앱으로, 실시간 동기화와 오프라인 지원을 핵심 가치로 합니다.

### 🏠 아키텍처 구조
- **Frontend**: React (Functional Components) + Context API (상태 관리)
- **Backend / DB**: Supabase (PostgreSQL + Realtime)
- **Serverless functions (Vercel)**:
  - `api/ocr.js`: Claude API를 이용한 영수증 및 카드 결제 내역 분석
  - `api/budget-ai.js`: 사용자 재무 상태 기반 AI 예산 추천
- **Deployment**: Vercel

## 2. 데이터 관리 전략 (Data Layer)
데이터베이스 설계가 전통적인 RDBMS 방식이 아닌, **Key-Value Store 스타일의 유연한 구조**를 채택하고 있습니다.

### 📅 데이터 스토리지 모델
- **Table Name**: `household_data`
- **Schema**:
  - `id` (householdId): 가계부 식별자 (예: 공유 코드)
  - `key`: 데이터 타입 (예: `tx_2026`, `fixed`, `plan`, `names`, `budgets`)
  - `value`: JSON 데이터
- **Lazy Loading (Task 4-2)**:
  - 지출 내역(`tx`)은 성능 최적화를 위해 연도별 키(`tx_YYYY`)로 분리하여 관리함.
  - 앱 초기 구동 시 현재 연도만 로드하고, 과거 데이터는 필요 시(`CalendarView`, `ReportView`) 호출함.

### ⚡ 실시간 동기화
- Supabase의 `postgres_changes` 구독을 통해 파트너가 데이터를 입력하면 즉시 자신의 화면에 반영됨.
- **오프라인 연동 (Task 5-3)**: 네트워크 단절 시 `localStorage`와 `offlineQueue`를 사용하여 데이터를 임시 저장하고, 온라인 복구 시 자동으로 서버로 전송(Flush)함.

## 3. 핵심 모듈 상세

### 📑 1. 카테고리 시스템 (`src/constants/index.js`)
총 9개의 기본 카테고리를 제공하며, 각 카테고리는 아이콘과 전용 컬러를 가짐.
- `food`, `housing`, `education`, `transport`, `medical`, `culture`, `clothing`, `sub`, `etc`

### 💰 2. 재무 플랜 (`EMPTY_PLAN`)
사용자의 고정 수입과 저축 목표를 관리함.
- `salary`: { husband: `number`, wife: `number`, savingsTarget: `number` }
- `utilizationTarget`: 예산 활용 목표 (보통 90% 또는 100%)

### 🤖 3. AI 및 OCR 기능 (`api/` 폴더)
- **OCR (Receipt/Card Scan)**:
  - Claude-3.5-Haiku 모델을 사용하여 이미지(Base64)에서 금액, 가맹점, 카테고리를 정밀 추출.
  - `bulk` 모드: 카드 앱 결제 내역 스크린샷에서 여러 건을 한 번에 추출 가능.
- **AI Budgeting**:
  - 가계 소득, 고정비, 저축 목표를 기반으로 9개 카테고리에 예산을 자동 배분.
  - 최근 3개월의 실제 지출 정보를 컨텍스트로 전달하여 맞춤형 추천 제공.
