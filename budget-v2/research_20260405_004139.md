# 💎 budget-v2 심층 분석 및 기술 명세 보고서 (Research Report)

> **작성일시**: 2026-04-05 00:41:39
> **대상**: `budget-v2` 폴더 전체 및 관련 아키텍처

본 보고서는 `budget-v2` 가계부 애플리케이션의 내부 작동 원리, 데이터 흐름, 상태 관리 전략 및 사용자 경험 최적화 기법을 기술적으로 상세히 분석한 결과입니다.

---

## 1. 애플리케이션 아키텍처 개요

`budget-v2`는 **React(Vite)** 기반의 프론트엔드와 **Supabase** 기반의 서버리스 백엔드를 결합한 하이브리드 실시간 가계부 앱입니다.

### 핵심 기술 스택
- **Frontend**: React 18, Vite, Context API
- **Backend**: Supabase (PostgreSQL + Realtime)
- **Styling**: Vanilla CSS (THEME_TOKENS 기반 디자인 시스템)
- **Persistence**: Supabase (Shared) + LocalStorage (Private/Queue)

---

## 2. 데이터 관리 및 동기화 메커니즘

### 2.1. 데이터 저장 구조 (Supabase `household_data`)
- **Key-Value 패턴**: 관계형 DB를 유연한 Key-Value 저장소로 활용합니다.
  - `id`: 가계부 고유 ID (Household ID)
  - `key`: 데이터 식별자 (예: `tx_2026`, `plan`, `fixed`, `cards`)
  - `value`: JSONB 타입의 실제 데이터 객체/배열
- **파티셔닝 (Lazy Loading)**: 거래 내역(`tx`)은 `tx_YYYY` 형태로 연도별로 분리되어 저장됩니다. 이는 데이터 증가에 따른 로딩 성능 저하를 방지하기 위한 핵심 전략입니다.

### 2.2. 실시간 동기화 (Realtime Pipeline)
1.  **쓰기**: `App.jsx`의 `setShared` 래퍼가 낙관적 업데이트(UI 즉시 반영) 후 Supabase `upsert`를 수행합니다.
2.  **구독**: `supabase.js`의 `subscribe` 함수가 PostgreSQL의 `UPDATE/INSERT` 이벤트를 리스닝합니다.
3.  **반영**: 파트너 기기에서 데이터 변경 시 실시간 브로드캐스트를 통해 `App.jsx`의 상태가 최신화됩니다.

### 2.3. 오프라인 안정성 (`offlineQueue.js`)
- 네트워크가 끊긴 상태에서 발생한 모든 `setShared` 요청은 `localStorage`의 `budget_offline_queue`에 저장됩니다.
- 브라우저가 다시 온라인 상태가 되면(`window.online` 이벤트), 큐에 쌓인 항목들을 Supabase로 일괄 재전송(Flush)하여 데이터 유실을 방지합니다.

## 3. 프론트엔드 로직 상세

### 3.1. 전역 상태 관리 (`BudgetContext.jsx`)
- **Prop Drilling 제거**: `App.jsx`에서 관리하는 모든 거대 상태(tx, plan, fixed 등)를 `BudgetContext.Provider`를 통해 하위 뷰에 주입합니다.
- **Selective Rendering**: 각 뷰는 `useBudget()` 훅을 사용하여 필요한 데이터만 선택적으로 소비합니다.

### 3.2. 데이터 무결성 검증 (`validate.js`)
- 저장 직전 데이터의 스키마 일치 여부를 확인합니다.
- 특히 `card.name` → `card.label`과 같은 필드명 변경 시 발생할 수 있는 런타임 오류를 사전 차단하기 위해 필수 필드 존재 여부를 체크하고 경고를 출력합니다.

---

## 4. UI/UX 및 디자인 시스템 (`globalStyles.js`)

### 4.1. 테마 및 디자인 토큰
- `THEME_TOKENS` (tokens.js) 기반으로 색상, 간격, 그림자, 곡률 등을 정의합니다.
- `globalStyles.js`는 CSS 변수를 활용하여 **다크(Dark)**, **라이트(Light)**, **올드스쿨(Oldschool)** 테마를 전환합니다.

### 4.2. 마이크로 애니메이션
- `u1`~`u6` 클래스를 통해 컴포넌트 진입 시 리드미컬한 상승(Slide Up) 효과를 부여합니다.
- 스피너 애니메이션(`spin`)과 페이드인(`fadeIn`)을 통해 로딩 및 동기화 상태를 시각적으로 피드백합니다.

## 5. 주요 기능별 작동 원리

| 기능 | 작동 방식 |
| :--- | :--- |
| **거래 입력** | `QuickEntrySheet` 또는 `EntryView`에서 입력 → `addTx` 호출 → `tx_YYYY` 상태 업데이트 → Supabase 저장 |
| **예산 설정** | `BudgetContext`의 `plan` 필드와 연동 → `budget-ai` 추천 로직(Optional) → `plan.salary` SSOT 유지 |
| **과거 조회** | `CalendarView`에서 연도 변경 → `loadTxYear(year)` 호출 → Supabase에서 해당 연도 `tx` Lazy Load |
| **동기화 바** | `syncStatus` 상태를 실시간 모니터링 → 상단 바 색상 및 텍스트(OK/Syncing/Error) 자동 변경 |

---

## 6. 결론 및 분석 총평

`budget-v2`는 **"단순하지만 강력한 실시간성"**과 **"데이터 안전성"**을 최우선으로 설계되었습니다. 단순한 배열 기반의 상태 관리에서 `tx` 파티셔닝과 Context API 도입을 통해 확장성이 확보되었으며, 오프라인 큐와 검증 레이어를 통해 엔터프라이즈 급의 데이터 정합성을 추구하고 있습니다.

현재의 구조는 향후 수천 건 이상의 데이터 환경에서도 안정적으로 동작할 것으로 판단되며, 기획된 Phase 5(UX 확장)로 나아가기에 충분히 견고한 기반을 갖추고 있습니다.
